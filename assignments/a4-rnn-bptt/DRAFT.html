The Setup

An RNN processes a three–step sequence (x₁, x₂, x₃). The hidden state updates as hₜ = f(xₜ, hₜ₋₁) and one scalar loss is taken at the end: L = L(h₃). Throughout I use the standard concrete form

hₜ = tanh( Wₕₕ hₜ₋₁  +  Wₓₕ xₜ  +  b )

Why RNNs are needed. A bag of words or an average of word vectors discards word order entirely — "good, not bad" and "bad, not good" produce the identical vector. An RNN instead reads the sequence one step at a time and carries a memory forward, so order is preserved by construction.

Q1Forward Pass

Start from h₀ = 0 (no context yet), then repeat one identical operation per step:

h₁ = tanh(Wₕₕ h₀ + Wₓₕ x₁ + b)
h₂ = tanh(Wₕₕ h₁ + Wₓₕ x₂ + b)
h₃ = tanh(Wₕₕ h₂ + Wₓₕ x₃ + b)
L  = L(h₃)

Three things follow directly:

  • Each step needs the previous one finished — h₂ cannot be computed before h₁ exists. The forward pass cannot be parallelised across time.
  • The same Wₕₕ, Wₓₕ, b appear in every line — one parameter set, reused at every step (Q6).
  • The loss is taken only at the end, yet h₁ and h₂ must still be corrected. That is the problem BPTT solves (Q3).
Draw this by hand — unrolled computational graph 
   h₀ ──Wₕₕ──▶ h₁ ──Wₕₕ──▶ h₂ ──Wₕₕ──▶ h₃ ───▶ L
                 ▲             ▲             ▲
              Wₓₕ│          Wₓₕ│          Wₓₕ│
                 x₁            x₂            x₃
Boxes for h₀..h₃ and x₁..x₃, horizontal arrows labelled Wₕₕ, vertical arrows labelled Wₓₕ, one arrow from h₃ to L. Use a ruler — this is the diagram the question explicitly asks for.

Reading it: two arrows enter every hidden state — one from that step's input, one from the previous hidden state. Only h₃ connects to the loss. The horizontal chain is the only route by which x₁ can influence L, and read backwards, the only route by which L can reach x₁'s parameters.

Q2Hidden State Dynamics

hₜ is the network's memory — a fixed-size summary of everything seen up to time t. Its size never changes, whether the network has read 3 words or 300. Constant memory cost, but finite capacity.

How context accumulates. Substituting each equation into the next:

h₂ = tanh( Wₕₕ · [ tanh(Wₕₕ h₀ + Wₓₕ x₁ + b) ] + Wₓₕ x₂ + b )
                   └────────── this is h₁ ──────────┘

Expanded fully, h₃ is a nested function of x₁, x₂ and x₃. Every input still has influence, but older information has been squeezed through tanh one more time at each step. That is the intuition behind vanishing gradients in Q7 — the maths there states the same observation precisely.

Q3Backpropagation Through Time

The loss is measured only at h₃, but the weights that produced h₁ and h₂ are equally responsible. So the error signal must travel backwards along the same chain the forward pass came along:

L  ──▶  h₃  ──▶  h₂  ──▶  h₁

Why "through time". In a feed-forward network, backpropagation travels backwards through layers — structures existing simultaneously in space. An RNN has only one cell; what looks like a stack of layers is the same cell at different moments. Travelling backwards therefore means stepping backwards through timesteps, not layers. Hence backpropagation through time.

Mechanically it is still just the chain rule. Two consequences follow from the structure, and each gets its own question: every hidden state must be stored (Q5), and the shared weights accumulate a gradient at every step (Q6).

Q4Chain Rule Derivation

L depends on h₁ only through h₂, which affects h₃. Applying the multivariable chain rule along that single path:

∂L/∂h₁  =  (∂L/∂h₃) · (∂h₃/∂h₂) · (∂h₂/∂h₁)

Step 1 — the loss term

With L = ‖h₃‖² = ∑ᵢ h₃,ᵢ² :

∂L/∂h₃  =  2 h₃

Step 2 — one step of recurrence (the important one)

Write the pre-activation aₜ = Wₕₕ hₜ₋₁ + Wₓₕ xₜ + b, so hₜ = tanh(aₜ). Then

∂hₜ/∂hₜ₋₁  =  diag( tanh′(aₜ) ) · Wₕₕ

Using the identity tanh′(a) = 1 − tanh²(a) = 1 − hₜ² :

∂hₜ/∂hₜ₋₁  =  diag( 1 − hₜ² ) · Wₕₕ        ← the Jacobian of one timestep

Step 3 — assemble

∂L/∂h₁  =   2h₃  ·  diag(1−h₃²)Wₕₕ  ·  diag(1−h₂²)Wₕₕ
            └──┬──┘    └───────┬───────┘    └───────┬───────┘
            ∂L/∂h₃        ∂h₃/∂h₂             ∂h₂/∂h₁

General form, for a sequence of length T

                          T
∂L/∂hₖ   =   (∂L/∂hᴛ)  ·   ∏   diag( 1 − hₜ² ) Wₕₕ
                        t = k+1
This product is the centre of the whole assignment Q5 follows because each Jacobian contains its own hₜ. Q6 follows because Wₕₕ appears in every factor. Q7 follows because a product of T terms grows or shrinks exponentially in T.

Verified. I computed ∂L/∂h₁ twice — once with PyTorch's autograd, once by evaluating the formula above directly. Maximum difference: 1.79 × 10⁻⁷, i.e. floating-point noise. The derivation is correct, not merely plausible.

Q5Intermediate Activations & Memory

Look again at the Jacobian from Q4:

∂hₜ/∂hₜ₋₁  =  diag( 1 − hₜ² ) Wₕₕ

It contains hₜ itself. The backward pass cannot evaluate this term without the numerical value the forward pass produced. So every hidden state must be kept, not discarded after use — the forward pass is not only computing an answer, it is recording the working the backward pass will need.

The cost: memory ∝ T × H, i.e. linear in sequence length. A 1,000-step sequence stores 1,000 hidden states before a single gradient is computed. This is a real engineering constraint, and it is why truncated BPTT (backpropagate only the last k steps) and gradient checkpointing (store some states, recompute the rest) exist.

Q6Parameter Sharing

Why the same weights at every step:

  • Sequences have no fixed length. Separate weights per timestep would mean a different model for every input length, and no way to handle anything longer than seen in training.
  • A pattern should be recognisable wherever it occurs. "not" should be understood the same way at position 2 or position 40.
  • Far fewer parameters — one matrix instead of T, cheaper and less prone to overfitting.

The effect on gradients — they SUM. Because Wₕₕ is used at every step it has many paths to the loss, and the chain rule requires adding each contribution:

                    T
∂L/∂Wₕₕ   =   ∑   (∂L/∂hₜ) · (∂hₜ/∂Wₕₕ)
                  t = 1

Note the summation. A non-shared parameter receives one gradient term; a shared one accumulates T of them. Two consequences: one update per parameter, not per timestep (all contributions are summed first, then a single update applied); and gradient magnitude scales with sequence length, which is part of why long sequences need careful learning rates and gradient clipping.

Q7Vanishing & Exploding Gradients

Straight from the general result in Q4, the gradient reaching an early timestep is a product of T−k matrices. Repeated multiplication is inherently unstable. Letting λ be roughly the largest singular value of one Jacobian:

‖ ∂L/∂hₖ ‖   ~   λᵣ⁻ᵏ
casewhat happensconsequence
λ < 1vanishes exponentiallyearly steps get no learning signal — no long-range dependencies
λ ≈ 1stablea knife-edge, not a region
λ > 1explodes exponentiallyenormous updates destroy the weights

Why tanh makes vanishing more likely. tanh′(a) = 1 − tanh²(a) ≤ 1, with equality only at a = 0. So the diag(1 − hₜ²) factor is always ≤ 1 and usually well below it, pushing λ downwards at every step regardless of Wₕₕ.

Measured, not just argued

I ran 30 timesteps with the spectral radius of Wₕₕ fixed exactly, and tracked the gradient norm at every step:

The key finding — the two failures are not symmetric Vanishing matches theory exactly; by t = 1 the gradient is around 10⁻¹⁹, numerically indistinguishable from no signal. Exploding is roughly 600× weaker than predicted, because as the gradient grows so does hₜ, and as hₜ approaches ±1 the factor (1 − hₜ²) collapses towards zero. The saturating non-linearity acts as its own brake on explosion.

This matters practically: explosion is loud and fixable by gradient clipping, whereas vanishing is silent — no error, no warning, the network simply never learns long-range structure. That is the harder failure, and it is what LSTM and GRU were designed to fix, using additive gated paths so gradients can cross many steps without being multiplied down at each one.

Q8PyTorch Implementation

I implemented a custom RNN cell in PyTorch rather than calling nn.RNN, so that all three parameters are explicit and each gradient can be inspected separately. The recurrence is written out by hand:

class SimpleRNNCell(nn.Module):
    def __init__(self, input_size, hidden_size):
        self.W_xh = nn.Parameter(torch.randn(hidden_size, input_size) * 0.5)
        self.W_hh = nn.Parameter(torch.randn(hidden_size, hidden_size) * 0.5)
        self.b    = nn.Parameter(torch.zeros(hidden_size))

    def forward(self, x, h_prev):
        return torch.tanh(self.W_xh @ x + self.W_hh @ h_prev + self.b)

Run over T = 5 timesteps (satisfying T ≥ 5), a scalar loss L = ‖h⁵‖² is taken at the final step, and .backward() called. Every parameter received a gradient:

What these gradients physically represent

Each number answers one precise question: if I increased this single parameter by a tiny amount, how much would the loss change? Formally p.grad[i,j] = ∂L/∂pᵢⱼ.

  • Sign — positive means increasing the weight increases the loss, so training should decrease it. This is why gradient descent subtracts: p −= lr × p.grad.
  • Magnitude — how strongly that weight influences the loss. Near zero means the loss is flat in that direction.

The specifically recurrent part. Because Wₕₕ is shared across all T steps, W_hh.grad is not the influence of one use — it is the sum of its influence at every timestep, exactly the summation derived in Q6. A single call to .backward() silently walked the chain from h⁵ back to h₁, computed a Jacobian at each step, and accumulated T contributions into one matrix. That is BPTT, performed automatically.

Conclusion

Everything in this assignment rests on one object — the product of Jacobians derived in Q4:

                          T
∂L/∂hₖ   =   (∂L/∂hᴛ)  ·   ∏   diag( 1 − hₜ² ) Wₕₕ
                        t = k+1

Q5 follows because each Jacobian needs its own stored hₜ. Q6 follows because Wₕₕ appears in every factor, so its gradients sum. Q7 follows because a product of T terms changes exponentially in T. The derivation was verified against autograd to 10⁻⁷, and the vanishing/exploding behaviour measured rather than assumed — revealing that the two failure modes are not symmetric, since tanh saturation damps explosion but nothing damps vanishing.
